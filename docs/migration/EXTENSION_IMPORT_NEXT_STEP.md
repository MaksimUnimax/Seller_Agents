# Следующий шаг: D1.E1 — перенос исходников и проверок

Статус: **PREPARED / NOT STARTED**. Исполнитель: архитектор объединения расширений.
Основание: [карта D1.E0](EXTENSION_IMPORT_MAP.md). Это ограниченный следующий этап после отчёта о карте; его описание не означает, что код уже перенесён.

## Результат

В Seller_Agents воспроизводится исходный Ozon 0.1.22. Исходный WB, его проверки и известный installed FAIL сохранены для последующей сверки. Производственный код не перепроектирован одновременно с изменением места хранения.

## Входы и область файлов

1. Повторно прочитать актуальный `main`, AGENTS, STATUS и [SOURCES](SOURCES.md). Проверить выбранные source commits и ZIP SHA-256 из [квитанции](evidence/extensions-2026-09-14/README.md). Изменение source branch не подменяет закреплённый источник автоматически; новая принятая версия требует явной замены карты.
2. Перенести 36/40 production-файлов точно по `planned_d1_path` в [RUNTIME_FILE_MAP](evidence/extensions-2026-09-14/RUNTIME_FILE_MAP.json). Сравнить каждый Git blob/SHA-256 и полный набор файлов. Source-ветки Blood & Sand не изменять.
3. Перенести заявленные тестовые входы по [TEST_AND_AUTHORITY_INPUTS](evidence/extensions-2026-09-14/TEST_AND_AUTHORITY_INPUTS.json). Для 20 исторических документов с `SOURCE_AUTHORITY_REFERENCE_ONLY` сохранить ссылки и хеши; не копировать старые отчёты с реальными данными аккаунтов. Проверить безопасность fixtures до включения в Git.
4. Добавить скрипты сборки/тестового layout и постоянный extension CI. Рабочие папки: `apps/extension`, `migration/reference`, extension-части `tests/regression`, `tests/fixtures/migration`, `tooling/build`, `tooling/checks`, соответствующий workflow и документация. Изменения workspace/lockfile — только если реально нужны инструментам, отдельным обозримым diff; внешние зависимости не обновлять попутно.
5. Оставить Ozon globals, manifest, storage keys и patch load order неизменёнными. Не добавлять новый UI, многомагазинность или серверную авторизацию в baseline-импорт. Это следующие вертикальные изменения D2/I1.

## Проверки переноса

| Gate | Что требуется |
|---|---|
| Source identity | 76/76 точных файлов, отсутствие посторонних runtime-файлов, Git blob и SHA-256 MATCH |
| Load graph | Все entrypoints и порядок загрузки совпадают с закреплёнными источниками |
| Ozon final source route | Перенесённые 10 верхнеуровневых gate-файлов, их входы, RED→GREEN и permission baseline выполняются в Seller_Agents по исходному маршруту |
| Воспроизводимые входы | 514 matrix и исторические fixtures читаются по закреплённым байтам; сеть/движущийся `origin/main` для получения fixture не нужны |
| Ozon exact package | Две сборки одним закреплённым упаковщиком совпадают; после распаковки совпадают набор и байты с импортированным source; обязательный пакетный маршрут повторяется на распакованном runtime |
| WB preserved route | Сохранить и запустить 52 исходных suite с их прежним donor; отличать воспроизведение прежних тестов от новой поведенческой и установленной приёмки |
| Изоляция | WB reference и historical fixtures не попадают в Ozon production ZIP; сервер и чужие контракты не меняются |
| Документы | Source mapping, commands, среда, hashes, exit codes, NOT_RUN/FAIL и следующий шаг опубликованы |

10 файлов проверок не равны 10 утверждениям/тестам. Повтор source suite на ZIP не удваивает покрытие. Если для переноса потребовалось изменить harness, изменение и основание показать отдельно; не ослаблять assertion ради зелёного результата.

Новый ZIP может отличаться от исходного SHA из-за явно выбранных правил упаковки. В таком случае доказать совпадение содержимого и воспроизводимость новой упаковки, зафиксировать новый hash; не подписывать его исходным `a3130816…`. Если заявлено точное воспроизведение старого ZIP, воспроизвести также порядок entries, directory records, timestamps, compression и среду исходного упаковщика.

## Граница завершения

Закрыть D1.E1 можно после remote readback и заявленных проверок исходников/пакета. Ozon LIVE CERTIFICATION остаётся PENDING до реальной установленной проверки; WB остаётся INSTALLED FAIL до исправления и принятого нового installed gate. Ни один из этих статусов не стирается зелёным CI переноса.

Не маскировать расхождения из [FINDINGS](evidence/extensions-2026-09-14/FINDINGS.md) исправлением во время копирования. На D2 отдельными изменениями: общее ядро и delivery, магазины/аккаунты/popup, часовой буфер, ручной режим, legacy import. Сначала воспроизвести исходное поведение, затем доказать изменённое.

Серверная параллель продолжается по своему поручению. Общий auth/sync contract меняет один назначенный автор; объединение расширений не задерживается до окончания всех серверных панелей. Ранний I1 остаётся в [общем roadmap](../ROADMAP.md).
