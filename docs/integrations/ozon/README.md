Активный источник для переноса: Ozon 0.1.22, `3b102f68a96bee0d7d734d7e32d4fccba440e927`. PRE-HANDOFF PASS, LIVE CERTIFICATION PENDING POST INSTALL. ## Собственная ответственность

Seller/Performance auth, фиксированные хосты, operations registry, схемы/serializer, значения API-лимитов, сроки/права/entitlements и verified identity.
Ozon Client-Id/Api-Key, Premium, FBO/FBS, SKU и прочие бизнес-сущности не становятся общими сущностями WB.
Два набора API относятся к одной карточке магазина, но их проверка и доступность независимы.

## Квоты

Существующий runtime содержит отдельные минутные ограничения для analytics_data/stock_turnover_analytics; при D1 проверить точные текущие значения и safety margin в исходном worker, не копировать числовые значения по памяти.
Общий локальный limiter должен связывать все диалоги и локальные дубликаты подтверждённого кабинета. Смена вкладки, имени или AI profile не сбрасывает ограничение.
Если API отвечает 429, результат сообщает операцию, факт rate limiting, известное ограничение и Retry-After при наличии.
Другой браузер/инструмент с тем же кабинетом — возможное объяснение, а не установленный факт. Если собственный журнал показывает нарушенный локальный интервал, это дефект расширения.
429 для операции без описанного минутного правила также не доказывает «Ozon сломан»: область ограничения может быть шире известной локальной политики.

Никакого cross-browser quota server. Ожидание до первого разрешённого запроса возможно; уже полученный 429 не вызывает скрытый повтор.
Стандарт 429 допускает Retry-After и не задаёт единую область подсчёта: [RFC 6585 §4](https://www.rfc-editor.org/rfc/rfc6585.html#section-4).
