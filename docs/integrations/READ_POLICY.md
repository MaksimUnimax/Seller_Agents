# Политика разрешённых API и инструкция API watcher

Цель — полное, доказанное разрешённое чтение, а не максимальное число добавленных методов.
Источник истины — свежая официальная спецификация и подтверждённый бизнес-эффект. Существующий registry является сравниваемой реализацией, не доказательством правильности собственной классификации.

## Для каждой операции

1. Получить полный официальный inventory METHOD + PATH, версии, дату и хеш исходника.
2. Разрешить ссылки схем, общие request/response definitions, вложенные объекты и выдаваемые файлы.
3. Прочитать назначение, эффект, вход, успешный/ошибочный ответ, auth/permissions, deprecation, сроки и lifecycle.
4. Определить, меняется ли постоянное бизнес-состояние продавца: заказ, цена, ставка, карточка, кампания, поставка, документ с юридическим действием.
5. Отдельно определить персональные данные, чувствительные операционные идентификаторы, права, доступность по тарифу, rate limit и безопасную передачу файла.
6. Выбрать primary class и независимые gates. Приложить точную ссылку/fragment и объяснение.
7. Сопоставить со старой классификацией и исполняемым registry: added/removed/changed/unchanged/HOLD.
8. Подготовить review diff, fixtures и предлагаемые изменения. Новые операции не включать автоматически.

## Классы

| Класс | Правило |
|---|---|
| READ_SAFE_DIRECT | Чтение без бизнес-мутации и дополнительных установленных gates |
| READ_SAFE_REPORT_START | Запускает получение/формирование отчёта, без бизнес-мутации |
| READ_SAFE_REPORT_STATUS | Проверяет состояние уже известной задачи отчёта |
| READ_SAFE_REPORT_DOWNLOAD | Получает готовый результат/файл |
| READ_SAFE_WITH_PRIVACY_GATE | Чтение с необходимым явным допуском персональных данных |
| CONDITIONAL_READ | Чтение с иным доказанным условием, чувствительными идентификаторами или ограниченным контекстом |
| MUTATION_BUSINESS_STATE | Меняет бизнес-состояние; запрещено продуктом |
| DEPRECATED_OR_RETIRED | Выведено/устарело по источнику; не считать новой действующей операцией |
| HOLD | Доказательств недостаточно; видимо в inventory, исполнение запрещено до решения |

POST не означает мутацию. Слово create/start не означает мутацию автоматически; GET и слово get не доказывают безопасность.
Создание задачи отчёта может быть read-safe, создание заказа — нет. Privacy gate независим от primary class: скачиваемый отчёт также может содержать персональные данные.
Разрешение read endpoint не означает разрешение автоматического polling/pagination его lifecycle.

## Контроль полноты

В inventory каждая METHOD + PATH ровно один раз; учтены все операции источника, включая HOLD/запрещённые/устаревшие.
Числа по непересекающимся primary classes дают полную сумму. Отдельные gates не прибавляются как новые операции.
Изменение shared schema повторно проверяет все зависимые операции, даже если path не менялся.
Нельзя выдавать «совпало со старой таблицей» за независимую проверку. Нельзя удалять неудобные/непонятные строки для достижения HOLD=0.
В runtime допускаются только строки с подтверждённым mapping, схемой, serializer и необходимыми gates. Coverage API не равен установленной успешности пользовательских задач.

## Зафиксированные ошибки прежнего Ozon-аудита

[Контрольный отчёт источника](https://github.com/MaksimUnimax/blood_sand/blob/17aa08335ee3acdc80cc7a093ddfa462198872f5/tooling/llm-api-bridges/ozon-seller/validation/FINAL_CONTROL_AUDIT_REPORT.md) содержит snapshot 514 операций: 299 read-capable, 183 business mutations, 32 deprecated.
Это исторические числа данного Swagger, не обещание текущего runtime.
36 прежних исправлений — расхождения классификации/gating; отчёт не подтверждает «36 пропущенных read-операций». Последующий control изменил четыре primary class и дополнительные privacy flags.
Пример report start: PERFORMANCE POST /api/client/statistics/phrases. Контрпример business mutation: SELLER POST /v2/order/create.
Особое внимание: issued exemplar/marks, GTD/RNPT/IMEI, history[].user_name, URLs документов и таможенных файлов. Эти поля нельзя считать обычным нечувствительным чтением только по имени endpoint.
30 primary privacy rows и 43 операции с privacy gate — разные измерения; их нельзя смешивать.

Watcher обязан сохранять эти примеры как regression fixtures и проверять будущие изменения семантически. Сам агент не выполняет реальные бизнес-команды для классификации.
