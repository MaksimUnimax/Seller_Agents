DESIGN
1. Private transport provenance in request().
Build URL/headers/body outside the fetch-only try/catch. If fetch rejects before returning Response, wrap it in a new CONTROL_TRANSPORT_UNAVAILABLE error and register its actual endpoint in a private WeakMap. No raw exception text, credentials or request body in public error/evidence.
A Response received followed by body-read failure, oversized body, JSON failure or validation failure is NOT transport. Do not classify by absence of failure.status, message text, navigator.onLine, caller-supplied flags or arbitrary errors with the same code. Preserve existing HTTP/error/size behavior.
This applies to actual request paths; no fallback for activation/exchange. No new timer, polling or retry loop.

2. Keep public bootstrap(options) online-only and its payload return shape unchanged.
Extract its existing body into a private online routine shared by bootstrap and a new privileged API bootstrapWithPolicy(options). Preserve option validation, auth/context ownership, bounded one-refresh-after-401, rotation persistence and all existing invalidation paths.
Each online invocation, including raw bootstrap calls from existing flows, increments a private bootstrap-attempt sequence. The policy invocation owns the exact sequence, generation/device/session and captured signed-cache identity. Do not expose any flag that lets callers declare a failure eligible.
Track whether this invocation observed a bootstrap401 before its forced refresh. A refresh network failure after that401 cannot mask the known auth challenge as offline. A preflight refresh transport failure before any auth-denial response may enter fallback, with the original rotation intent intact. Refresh503 is not eligible; only the audited bootstrap503 code is.
bootstrapWithPolicy returns {source:"ONLINE", freshness:"FRESH", payload:<clone>} after normal verified live success. Reject if ownership/snapshot changed before that public return. Do not change the raw bootstrap success/invalidation contract.

3. Fallback only at the policy acquisition boundary.
Capture the existing authority/envelope/binding before the online attempt. On eligible failure require the attempt sequence still current, context still owned, credentials valid, and exact captured authority identity still current. A raw bootstrap begun later also obsoletes the old fallback attempt. No matching cache means rethrow the original online failure, not cached success.
Allowed triggers: registered no-response transport from /v1/bootstrap or preflight /v1/auth/refresh; or HTTP503 BOOTSTRAP_UNAVAILABLE from requestBootstrap. All other HTTP results, malformed success, invalid signature, unknown key, incompatible signed policy, server-time regression, bad local storage and programming errors are ineligible. Never swallow 401/403 or replace a successful blocked policy with old cache. If the completed online routine still throws an unhandled401/403 from preflight/forced refresh while its original context remains current, run existing terminal invalidateKnown(context,failure,true) before returning the failure. If an existing invalidation already advanced generation, do not invalidate a second time. This closes the no-fallback-after-known-forbidden boundary durably without changing the one allowed bootstrap401 refresh attempt.
Reverify the captured envelope with the existing real verifyV2 and packaged ring; require canonical payload equality, validateAccountProfile with current environment, exact expectedCacheBinding, valid owned cacheClock, and exact requested-AI context. Missing detectedAi means account-only requested context, not permission to borrow a different AI snapshot.
Account-only verified cache may be returned as configuration; it still does not permit Work. No new capability names, no feature=true defaults, no profile execution or remote trust downloads.
After each asynchronous verification step and before/after the storage transaction recheck sequence and full authority identity. An old A response or crypto completion must not return B's payload or alter B's floor.

4. One bounded durable acquisition checkpoint in the existing mutationQueue.
Implement a private cachedBootstrapCheckpoint for this path using existing effectiveTime, persist, context and authority identity helpers; no second storage key/clock/auth stack.
Inside the queue, verify the captured identity and sequence again, compute effective time and advance state.cacheClock.effectiveTimeMs in memory before writing. Preserve the signed envelope/payload bytes and trusted-server floor.
Freshness: effective < expiresAt → FRESH; expiresAt <= effective < offlineGraceUntil → STALE_BUT_OFFLINE_GRACE_ELIGIBLE; effective >= offlineGraceUntil → deny CACHE_EXPIRED. Persist an observed expired floor too.
An increased floor must be durably written before returning a cached result. If AUTH set fails, attempt AUTH removal; any such checkpoint write failure denies this call. Both failures leave memory denied for this call and expose AUTH_DENIAL_PERSISTENCE_FAILED with an honest restart limitation. Never turn storage failure into transport fallback.
After the successful write take a completion-time sample and identity/sequence veto. Reclassify FRESH→STALE if needed; equality with offlineGraceUntil denies, advances/persists the denial floor and uses the existing removal fallback on write failure. The successful pre-write floor is the durable checkpoint; the later completion sample is a veto/runtime anchor, not falsely claimed durable.
Return {source:"CACHE", freshness, payload:<verified clone>} only after the last identity/sequence check. If no eligible result, throw a precise safe cache failure.
Do not set authority.workAllowed=true, runtimeLastCheckpointAllowed=true, or issue an authority-change grant from this API. Do not wire bootstrapWithPolicy into ensureForIdentity, canWork, status, getAuthority or application dispatch yet. Their existing fresh-only checks and expiry cleanup remain unchanged. The new result is configuration acquisition, not a Work token.
