# Octoport — product truth для SEO

Статус документа: **PRODUCT_TRUTH baseline**.
Дата: 2026-09-16.

Этот документ не описывает желаемые рекламные формулировки. Он ограничивает SEO тем, что продукт действительно представляет собой и что допустимо обещать пользователю.

## Бренд

- Публичное продуктовое имя: **Октопорт**.
- Латинская форма бренда и домена: **Octoport**, `octoport.ru`.
- `Seller_Agents` — техническое имя репозитория/историческое проектное имя, а не основной публичный бренд.
- Маскот: осьминог, визуально соединяющий ИИ/LLM с маркетплейсами.
- Будущий логотип: минималистичный векторный осьминог.

Маскот выражает механику продукта, но SEO не строится вокруг слова «осьминог». Поисковые страницы должны использовать язык задачи пользователя.

## Короткое определение продукта

`PRODUCT_TRUTH`: Октопорт — браузерное расширение, которое связывает выбранный пользователем веб-ИИ с разрешённым чтением данных его магазинов Ozon и Wildberries.

Целевое позиционирование: **«ИИ-сотрудник» продавца**. Пользователь предоставляет собственный LLM/подписку; Октопорт предоставляет безопасный мост к данным маркетплейса и доставляет результат обратно в тот же диалог.

## Базовая механика

Основной бизнес-путь данных:

`диалог с ИИ → расширение Октопорт → API Ozon/Wildberries → локальный результат → тот же диалог с ИИ`.

Обычный бизнес-запрос и сырой отчёт не должны проходить через сервер Октопорта. Сервер используется для аккаунта, авторизации, устройств, конфигурации, ограниченного service metadata, редкой синхронизации и администрирования.

## Launch-scope, который можно использовать в SEO

Допустимые продуктовые идеи, если конкретная страница не создаёт более сильного обещания:

- один продукт для Ozon и Wildberries;
- работа через выбранный пользователем ИИ;
- чтение доступных через разрешённые API данных магазина;
- получение и доставка отчётов/результатов в диалог;
- несколько магазинов как целевая продуктовая механика;
- ключи маркетплейсов локальны при обычной работе;
- нет server-side архива сырых бизнес-отчётов и истории чатов;
- первая бета планируется как ограниченная бесплатная бета;
- продукт ориентирован на данные и анализ, а не на изменение бизнес-состояния магазина.

## Что нельзя превращать в SEO-обещание без нового подтверждённого факта

- «регистрация уже открыта всем»;
- «продукт уже доступен в production»;
- «полностью поддерживаются все заявленные браузеры и все LLM»;
- «Октопорт вообще ничего не хранит на сервере»;
- «ключи никогда не взаимодействуют с сервером ни в каком сценарии» — есть отдельные механики авторизации/переноса, поэтому формулировка должна быть точной;
- редактирование цен, ставок, карточек, поставок или другого business state;
- автономная многошаговая работа без пользовательского подтверждения;
- собственная LLM/«наш ИИ»;
- облачный архив отчётов;
- исторические цены `199/299 ₽` как текущая публичная коммерческая политика;
- данные/функции, которых нет в разрешённых API Ozon/WB.

## Поисковая категория ещё не зафиксирована

Следующие формулировки — **SEARCH_HYPOTHESIS**, а не принятое название категории:

- ИИ для маркетплейсов;
- ИИ для Ozon / Озон;
- ИИ для Wildberries / WB;
- нейросеть для маркетплейсов;
- AI-помощник селлера;
- ИИ-помощник продавца маркетплейсов;
- ChatGPT для Ozon/Wildberries;
- аналитика маркетплейсов с ИИ;
- анализ продаж/рекламы/остатков маркетплейсов через ИИ;
- расширение для ChatGPT и маркетплейсов.

Какая из категорий должна стать основной SEO-категорией главной страницы, определяется только после Wordstat + intent/SERP анализа.

## Брендовые варианты для проверки

До появления собственного спроса фиксируем варианты, которые необходимо отслеживать, но не считаем их частотными:

- Октопорт;
- Octoport;
- окто порт;
- octo port;
- Октопорт Ozon;
- Октопорт Wildberries;
- Octoport Ozon;
- Octoport WB.

Это brand-defense / navigation set. Ошибочные написания расширяются только по фактическим Search Console/Вебмастер данным или живому Wordstat спросу.

## Аудитории: что известно и что пока гипотеза

`PRODUCT_TRUTH`: основной пользователь — продавец, которому нужны данные его магазинов Ozon/Wildberries и который уже использует или готов использовать внешний LLM.

`SEARCH_HYPOTHESIS`: отдельные страницы/кластеры могут понадобиться для:

- самостоятельного селлера;
- менеджера маркетплейсов;
- агентства/команды, ведущей несколько магазинов;
- специалиста по рекламе;
- аналитика e-commerce.

Нельзя создавать отдельную persona-страницу без подтверждения отдельного интента или явной продуктовой необходимости.

## Брендовая визуальная метафора

Осьминог соединяет две группы объектов:

1. LLM / веб-ИИ — ChatGPT, Алиса и другие поддерживаемые адаптерами интерфейсы;
2. маркетплейсы — Ozon и Wildberries.

Для визуального языка допустимо показывать несколько «щупалец» к AI и крупные, отчётливо отличимые marketplace endpoints. В SEO-копирайтинге эта метафора используется как объяснение бренда, но не должна ухудшать ясность ответа на запрос пользователя.

## Правило для будущих page specs

Каждая страница обязана отвечать одновременно на три вопроса:

1. Какой поисковый интент она закрывает?
2. Какую реальную задачу Октопорт решает для этого интента?
3. Какое утверждение на странице доказывается текущим product truth, а не маркетинговой фантазией?

Если на второй или третий вопрос нет точного ответа, страница не должна становиться SEO target page.
