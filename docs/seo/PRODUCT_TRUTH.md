# Octoport — product truth для SEO

Статус документа: **PRODUCT_TRUTH baseline / OWNER-CORRECTED**.
Дата: 2026-09-16.

Этот документ не описывает желаемые рекламные формулировки. Он ограничивает SEO тем, что продукт действительно представляет собой и что допустимо обещать пользователю.

## Бренд

- Публичное продуктовое имя: **Октопорт**.
- Латинская форма бренда и домена: **Octoport**, `octoport.ru`.
- `Seller_Agents` — техническое имя репозитория/историческое проектное имя, а не основной публичный бренд.
- Маскот: осьминог, визуально соединяющий ИИ/LLM с маркетплейсами.
- Будущий логотип: минималистичный векторный осьминог.

Маскот выражает механику продукта, но SEO не строится вокруг слова «осьминог». Поисковые страницы должны использовать язык задачи пользователя.

## Короткое определение продукта

`PRODUCT_TRUTH`: **Октопорт — не собственный ИИ-сотрудник и не собственная LLM. Октопорт — браузерный мост/инструмент, который превращает выбранный пользователем поддерживаемый веб-ИИ в сотрудника для работы с его Ozon и Wildberries, предоставляя этому ИИ разрешённый доступ к данным/инструментам маркетплейса и возвращая результат в тот же диалог.**

Ключевая формула продукта:

`выбранный пользователем ИИ -> Octoport -> разрешённые данные/инструменты Ozon/Wildberries -> тот же ИИ работает как сотрудник селлера`.

Пользователь приносит собственный LLM/подписку; Октопорт предоставляет безопасный мост к маркетплейсу. Поэтому публичное позиционирование не должно подменять Октопорт словами «наш ИИ», «наш агент» или «Октопорт сам является сотрудником».

## Базовая механика

Основной бизнес-путь данных:

`диалог с выбранным ИИ -> расширение Октопорт -> API Ozon/Wildberries -> локальный результат -> тот же диалог с ИИ`.

Обычный бизнес-запрос и сырой отчёт не должны проходить через сервер Октопорта. Сервер используется для аккаунта, авторизации, устройств, конфигурации, ограниченного service metadata, редкой синхронизации и администрирования.

## Launch-scope, который можно использовать в SEO

Допустимые продуктовые идеи, если конкретная страница не создаёт более сильного обещания:

- один продукт для Ozon и Wildberries;
- работа через выбранный пользователем ИИ;
- превращение поддерживаемого пользовательского ИИ в помощника/сотрудника по работе с маркетплейсом;
- чтение доступных через разрешённые API данных магазина;
- получение и доставка отчётов/результатов в диалог;
- анализ seller-owned данных и помощь в понимании кабинета, отчётов и операционных задач в пределах доступных источников;
- несколько магазинов как целевая продуктовая механика;
- ключи маркетплейсов локальны при обычной работе;
- нет server-side архива сырых бизнес-отчётов и истории чатов;
- первая бета планируется как ограниченная бесплатная бета;
- launch-продукт ориентирован на чтение данных, анализ, объяснение и подготовку работы, а не на изменение business state магазина.

## Поисковые задачи, которые потенциально относятся к нашей аудитории

SEO не ограничивается людьми, которые уже знают новую категорию «ИИ-сотрудник». В существующем спросе потенциально наши клиенты могут искать более старые категории/формулировки:

1. ИИ-агент / ИИ-ассистент для Ozon/Wildberries;
2. подключение ChatGPT/Claude/Gemini/другого ИИ к кабинету или данным маркетплейса;
3. аналитика кабинета продавца, сервис аналитики маркетплейсов, отчёты селлера, продажи, прибыль, остатки, поисковые запросы, возвраты и другие seller-data задачи;
4. помощь в ежедневной работе с кабинетом: товары, поставки, заказы, отзывы, цены, отчёты, правила и функции кабинета;
5. помощь с карточкой товара как рабочей задачей — структура, характеристики, описание, SEO, проверка, подготовка — но не отдельный рынок AI-генераторов изображений/инфографики;
6. рекламная аналитика, отчёты, диагностика, объяснение показателей, рекомендации и планирование — но не отдельная категория real-time autobidder/ботов ставок;
7. marketplace/search/niche analytics только там, где такие данные действительно доступны из подтверждённых Ozon/WB источников.

Эти направления являются `SEARCH_HYPOTHESIS` до Wordstat + SERP + competitor/Alice проверки. Само наличие задачи не означает, что под неё нужна отдельная страница.

## Что нельзя превращать в SEO-обещание без нового подтверждённого факта

- «регистрация уже открыта всем»;
- «продукт уже доступен в production»;
- «полностью поддерживаются все заявленные браузеры и все LLM»;
- «Октопорт вообще ничего не хранит на сервере»;
- «ключи никогда не взаимодействуют с сервером ни в каком сценарии» — есть отдельные механики авторизации/переноса, поэтому формулировка должна быть точной;
- редактирование цен, ставок, карточек, поставок или другого business state в launch-scope;
- автономная многошаговая работа без пользовательского подтверждения;
- собственная LLM/«наш ИИ»;
- формулировка «Октопорт сам является ИИ-сотрудником»;
- облачный архив отчётов;
- исторические цены `199/299 ₽` как текущая публичная коммерческая политика;
- данные/функции, которых нет в разрешённых API Ozon/WB;
- полный внешний market-intelligence/competitor/niche coverage без endpoint-level подтверждения;
- обещание real-time автоматического управления рекламными ставками как основной продуктовый сценарий.

## Поисковая категория ещё не зафиксирована

Следующие формулировки — **SEARCH_HYPOTHESIS**, а не принятое название категории:

- ИИ для маркетплейсов;
- ИИ для Ozon / Озон;
- ИИ для Wildberries / WB;
- ИИ-агент / ИИ-ассистент для маркетплейсов;
- ИИ-помощник селлера;
- «ИИ-сотрудник» продавца/маркетплейса как новая объясняющая категория;
- ChatGPT/Claude/Gemini для Ozon/Wildberries;
- подключить ИИ к кабинету/данным маркетплейса;
- аналитика маркетплейсов / кабинета селлера;
- отчёты и анализ продаж/рекламы/остатков через ИИ;
- помощь в работе с кабинетом маркетплейса;
- помощь с карточками товара как операционной задачей;
- расширение/мост между LLM и маркетплейсами.

Какая формулировка должна стать основной SEO-категорией главной страницы, определяется только после Wordstat + intent/SERP + competitor/Alice анализа. Новизна продукта означает, что основной коммерческий спрос может приходить через старые категории, даже если ни одна из них не описывает Октопорт полностью.

## Аудитории: что известно и что пока гипотеза

`PRODUCT_TRUTH`: основной пользователь — продавец/команда продавца, которым нужно дать уже используемому или выбранному внешнему ИИ доступ к разрешённым данным Ozon/Wildberries, чтобы этот ИИ помогал работать с магазином.

`SEARCH_HYPOTHESIS`: отдельные страницы/кластеры могут понадобиться для:

- самостоятельного селлера;
- менеджера маркетплейсов;
- агентства/команды, ведущей несколько магазинов;
- специалиста по рекламе;
- аналитика e-commerce;
- пользователя аналитического/отчётного сервиса, который ищет более удобный способ работать с seller data;
- пользователя ChatGPT/Claude/Gemini, который хочет подключить свой ИИ к маркетплейсу.

Нельзя создавать отдельную persona-страницу без подтверждения отдельного интента или явной продуктовой необходимости.

## Брендовая визуальная метафора

Осьминог соединяет две группы объектов:

1. LLM / веб-ИИ — ChatGPT, Алиса и другие поддерживаемые адаптерами интерфейсы;
2. маркетплейсы — Ozon и Wildberries.

Для визуального языка допустимо показывать несколько «щупалец» к AI и крупные, отчётливо отличимые marketplace endpoints. В SEO-копирайтинге эта метафора используется как объяснение бренда, но не должна ухудшать ясность ответа на запрос пользователя.

## Правило для будущих page specs

Каждая страница обязана отвечать одновременно на четыре вопроса:

1. Какой поисковый интент она закрывает?
2. Какую реальную задачу пользователь пытается решить?
3. Как Октопорт позволяет выбранному пользователем ИИ решать эту задачу?
4. Какое утверждение на странице доказывается текущим product truth, а не маркетинговой фантазией?

Если на третий или четвёртый вопрос нет точного ответа, страница не должна становиться SEO target page.
