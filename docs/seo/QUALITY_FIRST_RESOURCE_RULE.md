# Octoport SEO — quality-first resource rule

Status: **ACTIVE / OWNER-LOCKED / HARD RULE**.
Date: 2026-09-16.

## Owner directive

For this SEO/semantic research program:

```text
QUALITY OF THE FINAL DECISION
> PROVIDER QUERY COST
> TOKEN COST
> WORK COMPUTE / EXECUTION COST
> SPEED / CONVENIENCE
```

There is no owner-imposed economy cap on provider requests, ChatGPT Work usage, model tokens, deep analysis passes, independent audits or reruns when they can materially improve correctness, completeness or decision quality.

## What this changes

1. Never skip a materially useful Wordstat/Search/Alice/provider query because it costs money.
2. Never keep a historically completed step merely to avoid rerunning it if corrected product truth or new evidence makes a rerun analytically useful.
3. Never reduce a large-data task to samples/first-N/truncated context merely to save model tokens or Work resources.
4. Use ChatGPT Work proactively when full-volume deep analysis, cross-source reconciliation, classification, clustering, independent QA or large corpus review will improve quality.
5. Multiple independent analytical passes are allowed and expected when a high-value decision remains ambiguous.
6. Cost can still be recorded for provenance/operations, but it is **not** a decision criterion for evidence acquisition unless the owner explicitly changes this rule.
7. Do not make redundant calls that have no expected information gain. `NO ECONOMY CAP` does not mean random duplication; every call/rerun still needs a named analytical purpose.

## Work policy

Work is not a last-resort context overflow mechanism. It is a preferred full-volume execution environment whenever deeper treatment materially improves confidence or auditability.

Examples:

- full semantic ledger classification;
- cross-source Wordstat + SERP + competitor + Alice reconciliation;
- large competitor-page corpus extraction/comparison;
- pairwise SERP-overlap matrices;
- ambiguous family-level semantic audits;
- independent adversarial re-checks;
- reruns after product-truth correction;
- complete row-level QA where ordinary chat would be less reliable.

No fixed row-count threshold. Trigger is expected quality gain.

## Acceptance principle

```text
CHEAPER / FASTER / FEWER TOKENS
```

is never a valid reason to accept a materially weaker SEO/semantic result.

The only valid reason not to perform an additional query or Work pass is that it has no material expected information gain for a current or foreseeable decision.
